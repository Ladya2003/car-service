# Смена — демо автосервиса

Сайт: https://ladya2003.github.io/car-service/
Кабинет: https://ladya2003.github.io/car-service/admin/

Вымышленная СТО в Фаниполе. Реальное обслуживание, звонки и SMS не выполняются. Для тестов используйте вымышленные данные. Пароль — в **MVP-access.local.txt**, файл игнорируется git и передаётся партнёру отдельно.

## Возможности
Статическая главная и шесть страниц услуг; запись без регистрации; календарь свободного времени; заявки, статусы, заметки и переносы; ручная телефонная запись; рабочие дни, часы, перерывы и до четырёх постов. Защита одновременного бронирования и повторной отправки. Подготовлена очередь Telegram-уведомлений.

## Запуск
Node.js 22+. Фронтенд без внешних npm-зависимостей.
~~~
npm run dev
~~~
Открыть http://127.0.0.1:4175/car-service/

Отдельным процессом:
~~~
cd ../Amorely/server
node -r ts-node/register scripts/car-service-dev.ts
~~~
API: http://127.0.0.1:5086/api/car-service. Используется MONGODB_URI из существующего server/.env. Отдельный запуск не выполняет миграции остальных модулей Amorely.

Первичная настройка:
~~~
cd ../Amorely/server
node -r ts-node/register scripts/car-service-provision.ts
~~~
Создаются только car_service_workspace и car_service_access в существующей базе, новая БД не создаётся. Повторный запуск не меняет пароль. Вход отделён от аккаунтов/JWT Amorely; пароль хранится как bcrypt-хеш, ключ сессий отдельный.

## Проверки
~~~
npm test
node tests/api-smoke.mjs
node scripts/browser-qa.mjs
~~~
Для двух последних должны работать локальные фронт и API. Они создают и удаляют только собственные тестовые записи. Нужен соседний Amorely/server с зависимостями и БД. Для модульных тестов другой путь можно задать AMORELY_SERVER_DIR. Браузерная проверка использует установленный Chrome и сохраняет снимки в .runtime/screenshots (gitignored).

Бэкенд: из Amorely/server выполнить node node_modules/typescript/bin/tsc --noEmit. Обычный npm run build Amorely также запускает существующий загрузчик изображений, для проверки модуля он не требуется.

## Telegram — подключить позже
Создайте отдельного бота через @BotFather и добавьте в закрытую группу с правом отправки. В окружение Amorely на Render добавьте:
~~~
CAR_SERVICE_TELEGRAM_BOT_TOKEN=
CAR_SERVICE_TELEGRAM_CHAT_ID=
CAR_SERVICE_ADMIN_URL=https://ladya2003.github.io/car-service/admin/
~~~
Токен — только на сервере, не в config.js и не в git. chat_id группы обычно отрицательный. Его можно получить через getUpdates после команды боту в группе; ответ не публикуйте.

После перезапуска статус подключения появится в Настройках. Новые заявки отправляются автоматически; накопленная очередь тоже будет обработана. При сбое Telegram заявка сохраняется. До пяти повторных попыток, затем ручной повтор из кабинета. При неопределённом сетевом результате возможно повторное уведомление — ориентируйтесь на номер заявки.

## Публикация
.github/workflows/pages.yml собирает web/ в dist/ и публикует только его. GitHub Pages → Source: GitHub Actions. Исследование и локальные файлы на сайт не попадают. CAR_SERVICE_API_URL при сборке — публичный адрес API.

Код API: соседний Amorely/server/src/carService и server/src/routes/carService.ts. Подключён до общей авторизации Amorely. CORS учитывает CLIENT_URL, дополнительный CAR_SERVICE_ORIGINS и ваш GitHub Pages origin.

Для демо установлен noindex/Disallow: /. У реального сервиса до индексации замените вымышленные материалы, адрес, цены и страницу обработки данных. Главная/услуги содержат готовый HTML. SEO-подготовка не гарантирует трафик.

## Ограничения
Одна СТО, горизонт 60 дней, начало каждые 30 минут, минимум за час до визита; до 2000 заявок и 500 перерывов. Каталог фиксирован в backend. Изменения расписания используют атомарную проверку версии единственного документа; отдельная архитектура нескольких организаций не создавалась.

Сессия администратора в sessionStorage на 8 часов. Телефоны доступны только после входа. Есть ограничения частоты входа и заявок. Для коммерческого запуска нужны отдельная проверка эксплуатации/данных, резервное хранение, защита от спама и согласование поддержки.
